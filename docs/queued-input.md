# 대기 메시지

실행 중 입력한 메시지는 FIFO 대기열에 보관합니다. 전송 동작은 현재 실행을 중지하거나 런타임에 추가 지시를 보내지 않습니다. 본문과 첨부 이름은 입력창 위의 **대기 메시지** 목록에 표시하며, 런타임이 해당 요청을 접수한 뒤에만 사용자 메시지를 대화에 추가합니다. 빈 입력창의 중지 버튼과 Esc는 기존의 명시적 실행 중지 동작입니다.

## 처리 정책

| 상황 | 대기열 처리 |
| --- | --- |
| 현재 실행 완료·실패·명시적 취소 결과 확인 | 다음 요청부터 순서대로 실행합니다. |
| 사용자 결정 필요 | 대기열을 유지합니다. 승인 버튼이나 새로 작성한 답변을 먼저 처리한 뒤 대기열을 계속합니다. |
| 상태 조회·연결 실패 | 실행 종료를 추정하지 않습니다. 현재 실행 ID와 대기열을 유지하고, 재연결 또는 **실행 상태 확인 후 대기열 계속**으로 상태를 다시 확인합니다. |
| 요청 접수 확인 실패 | 자동 재전송하지 않습니다. 대기 목록에서 **입력창으로 복원**할 수 있습니다. 실제 접수 여부가 불명확한 경우 실행 기록을 확인한 후 재전송해야 합니다. |
| 화면 재연결 | 호스트가 보관한 접수 알림을 재전달하며 메시지 ID로 중복 표시를 방지합니다. |
| 확장 호스트 재시작 | 화면에 저장된 미처리 입력을 보존하되 자동 재전송하지 않습니다. 호스트의 메모리 큐를 잃은 항목은 입력창으로 복원할 수 있습니다. |

각 요청은 입력 시 선택한 작업 모드, 모델, 추론 수준, Fast, Goal·목표와 첨부를 보관합니다. 실행 권한은 호스트가 메시지를 받을 때 캡처하며, 첨부 준비가 끝나기를 기다리는 동안의 설정 변경에 영향을 받지 않습니다. 대기 입력을 추가해도 현재 실행의 시작 시간·진행 표시·하위 에이전트 목록은 초기화되지 않습니다.

호스트 준비 작업은 직렬화하며, 같은 메시지 ID의 중복 수신은 다시 제출하지 않습니다. 접수 알림과 화면 보관 목록은 채팅 패널 단위입니다. 프로세스 종료를 넘는 런타임 제출의 원자적 중복 제거는 제공하지 않으므로, 접수 여부가 불명확한 요청은 자동 재시도하지 않습니다.

## Main 확인 명령

Work는 테스트·빌드·검증 명령을 실행하지 않습니다. 다음은 Main이 실행할 범위입니다.

```sh
npm run typecheck
node --check static/js/chat.js
node --test tests/unit/queue-lifecycle.test.mjs tests/unit/work-loop-button.test.mjs
node --test --test-name-pattern='queue|FIFO|reconnect|Goal control serializes|decision' tests/unit/runtime-adapter.test.mjs
node --test tests/unit/structure.test.mjs tests/unit/status-customization.test.mjs
```

화면 확인에서는 실행 중 여러 입력을 연속 전송한 뒤 대기 목록·접수 후 대화 표시·명시적 중지·사용자 결정·이미지 첨부·화면 재연결을 확인합니다.
